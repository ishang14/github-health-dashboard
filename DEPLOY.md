# Deployment

The app is two stateless containers plus MongoDB (Atlas or self-hosted):

| Piece  | Image                          | Port | Notes |
|--------|--------------------------------|------|-------|
| server | `server/Dockerfile` (Node 20) | 5000 | Express API, reads config from env |
| client | `client/Dockerfile` (nginx)   | 80   | static SPA; API URL baked at build time |
| db     | MongoDB 7                      | 27017| external (Atlas) or the `local-db` compose profile |

Because MongoDB is external, **this runs on any container host** — Render,
Railway, Fly.io, DigitalOcean App Platform, a VPS with Docker, ECS, etc.
Render is just one option; a blueprint is included for it.

---

## 1. Local / self-hosted with Docker Compose

```bash
cp server/.env.example server/.env      # fill in GITHUB_TOKEN, MONGODB_URI, JWT_SECRET
docker compose up --build
# client  -> http://localhost:8080
# server  -> http://localhost:5000
```

Throwaway local database instead of Atlas:

```bash
# in server/.env:  MONGODB_URI=mongodb://mongo:27017/githealth
docker compose --profile local-db up --build
```

For a real deployment behind a domain, change:

- `docker-compose.yml` → `server.environment.CLIENT_ORIGIN` = the client's public URL
- `docker-compose.yml` → `client.build.args.VITE_API_BASE_URL` = the server's public URL + `/api`
- `server/.env` → `SNAPSHOT_INTERVAL_MINUTES=60` (dev uses `0`)

Then put a TLS-terminating reverse proxy (Caddy, Traefik, nginx) in front.

## 2. Render (blueprint)

1. Push this repo to GitHub.
2. Render dashboard → **New + → Blueprint** → select the repo. It reads
   [`render.yaml`](render.yaml) and creates:
   - `githealth-api` — Docker web service from `server/Dockerfile`
   - `githealth-web` — static site (`npm run build` → `client/dist`, SPA rewrite)
3. Set the values Render prompts for (`sync: false`):
   - `githealth-api`: `GITHUB_TOKEN`, `MONGODB_URI` (Atlas SRV string), `CLIENT_ORIGIN`
   - `githealth-web`: `VITE_API_BASE_URL`
4. First deploy is a chicken/egg on URLs. Deploy once, copy the two URLs, then:
   - set `githealth-api` → `CLIENT_ORIGIN` = `https://githealth-web.onrender.com`
   - set `githealth-web` → `VITE_API_BASE_URL` = `https://githealth-api.onrender.com/api`
   - redeploy both (the web one must rebuild to bake the new URL).
5. `JWT_SECRET` is auto-generated by Render. Atlas: allow Render egress IPs or
   `0.0.0.0/0` in Network Access.

Prefer containers for both? Replace the `githealth-web` service in `render.yaml`
with `runtime: docker`, `dockerfilePath: ./client/Dockerfile`, and pass
`VITE_API_BASE_URL` as a Docker build arg (`dockerCommand` not needed).

## 3. Other hosts

- **Railway / Fly.io**: one service per Dockerfile. Set the same env vars.
  Fly: `fly launch` in `server/`, then in `client/` with
  `--build-arg VITE_API_BASE_URL=...`.
- **Single VPS**: `docker compose up -d` + Caddy for automatic HTTPS.
- **Kubernetes**: two Deployments + Services; put `VITE_API_BASE_URL` in the
  image build pipeline, everything else in a Secret/ConfigMap.

## Environment variables

### server

| Key | Required | Notes |
|-----|----------|-------|
| `GITHUB_TOKEN` | yes | GitHub PAT, public-repo read |
| `MONGODB_URI` | yes | Mongo connection string |
| `JWT_SECRET` | yes in prod | server refuses to start in `NODE_ENV=production` without it |
| `JWT_EXPIRES_IN` | no | default `7d` |
| `CLIENT_ORIGIN` | yes | exact origin(s) of the client, comma-separated; drives CORS |
| `PORT` | no | default `5000` |
| `SNAPSHOT_INTERVAL_MINUTES` | no | default `60`; `0` records every analysis |
| `NODE_ENV` | recommended | set to `production` |

### client (build-time only)

| Key | Notes |
|-----|-------|
| `VITE_API_BASE_URL` | full URL of the API incl. `/api`; baked into the bundle. Users can still override it per-browser on the Settings page. |

## Pre-flight checklist

- [ ] Rotated the `GITHUB_TOKEN` and MongoDB password that were committed earlier.
- [ ] `JWT_SECRET` is a long random value (not the dev fallback).
- [ ] `CLIENT_ORIGIN` matches the client URL exactly (scheme + host + no trailing slash).
- [ ] `VITE_API_BASE_URL` points at the deployed API and ends in `/api`.
- [ ] Atlas Network Access allows the host's egress IPs.
- [ ] `SNAPSHOT_INTERVAL_MINUTES` set to `60` for production.
